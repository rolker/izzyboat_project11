### Operator Corrections

- **Power-loss mechanism (corrects salmon's "brownout" framing).** Operator: the batteries shut down at a critical voltage via BMS cutoff, so **the whole boat goes dark suddenly** — it is *not* a gradual telemetry brownout. There is zero graceful degradation, so any low-battery alarm must fire well *above* the BMS cutoff to be useful. Tow was pure power exhaustion (no other contributing fault reported).
- **Trackline failure signature (refines #311).** Operator: a multi-segment trackline runs fine for the first few segments, then takes off in the wrong direction **at a segment transition**. (Not a from-execution-start failure.) Add today's recurrence to #311.
- **Down-view sonar — walks back gabby's conclusion.** Operator: setting the sidescan **`range_m` to 5 m got the down-view channel auto-tracking the bottom again**. gabby's logged conclusion that `range_m` affects only the sidescan channel and the down-view stuck-at-~1.8 m was independent/device-side is incorrect — there is a real cross-channel interaction.
- **Issue identity (corrects salmon's #309 instruction).** salmon instructed linking today's logs to #309 ("do not create a new issue"). #309 is *yesterday's* (2026-06-22) deployment, already closed; #311/#312 are its RCAs. Today is **#313**. gabby + salmon logs linked to #313; markers cleared.
- Start date 2026-06-23 confirmed correct; operator reported nothing missing from the logs.

### Lessons Learned

- No low-battery alarm fired before total shutdown. MAVROS battery config lacks low/critical voltage thresholds and pack capacity, so no SOC% and no alarm — and because the BMS cutoff is instantaneous, the alarm must be configured with margin above cutoff, not at it. Highest-priority fix before next outing.
- FCU dataflash logging is disabled on this boat (LOG_BACKEND_TYPE=0); reconstruct V/I history from the boat bag `/bizzy/mavros/battery`, not onboard FCU logs.
- `mission_plan` + `mission_manager/command` are now in the boat-side `logger` record list (`bizzyboat.yaml`, takes effect next rebuild+relaunch) — enables commanded-vs-actual trackline analysis next run.
- Issue-less field starts (#533) on gabby/salmon worked, but the same-site/same-symptom overlap with the prior day's #309 led salmon to a wrong issue-attribution conclusion. The dev session had already created #313 — propagation/visibility lag between dev-created issue and field hosts is the gap.
- salmon idea: oversized CAMP background GeoTIFFs (e.g. 28032×4480) load slowly; pre-downsample/retile for faster CAMP load.
