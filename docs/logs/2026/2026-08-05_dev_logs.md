## Lessons Learned

- An AIMD/admission-controlled link must be sampled over a window, never once — three separate single-sample mis-reads this session (16:41 "regression", 16:47 "recovered", corrected at 17:07).
- Dockside link measurements cannot drive link selection: WiFi is line-of-sight only; VPN (Starlink) is the sole over-the-horizon carrier, so congestion must be solved within the VPN budget.
- Deliberate sender-side shedding beats wire loss for fragmented messages: one lost fragment kills the whole message, and the resends compound the congestion that caused the loss.
- Lowering a connection cap shrinks the instantaneous headroom the largest message must fit into — the 1.5→1.0 MB/s cap cut helped every topic except the ~183 KB coverage tiles it was meant to save.
- Field-tuned runtime parameters are silently lost at relaunch; the OAK 100 kbps setting was caught and persisted just before the relaunch that would have reverted it. `/parameter_events` is now bagged (08-04 gap closed), so live tuning is reconstructable from bags.
- A boat-side coverage reset does not clear CAMP's operator-side tile cache — a surprising, undocumented asymmetry.
- `issue_sync.field_pull` ("git bug pull origin") fails in agent Bash subshells (no SSH agent); the plain-git fetch of `refs/bugs/*` works — deployment.yaml candidate change.
- Shallow water inverts geometric assumptions tuned in deep water: line spacing follows swath width follows depth, which is why the RobotOnPath 5.0 m guard only failed here.
