## Lessons Learned

- **A config edit is not live until the process restarts, and nothing says so.** `bizzyboat.yaml` was
  edited at 12:15:13; udp_bridge had started at 12:04:52 and ran all day on the pre-edit config. The
  symlink install means the file on disk is already correct, which makes the staleness *less* visible,
  not more. The agent caught it only by dumping the live node and counting topics.
- **A working page is not evidence that the intended path works.** Coverage reached the operator over
  a direct `rmw_zenoh` route, not the bridge. Everything looked right while the configured mechanism
  was doing nothing — and would have stopped the moment the direct route dropped or the link fell back
  to cell.
- **The agent flagged the re-enabled cell path as probably unintended and was right to, even though
  the answer was that a SIM had been fitted.** Flagging a config change against the file's own recorded
  rationale cost nothing and surfaced a fact the file did not know.
- Radio-level RSSI is not readable from gabby — it lives on the Teltonika routers. Throughput and loss
  stayed flat to 993 m, so RSSI is the better early-warning metric if range margin ever matters, and it
  is currently not collected.
